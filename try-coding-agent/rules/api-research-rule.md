# API仕様調査ルール

## 基本方針

Win32 API、DirectX 12、DXGI、D3D12、WICなど、Microsoftが仕様を管理するAPIを実装するときは、Microsoft Learnを第一優先の資料とする。

Microsoft Learn MCPが利用可能な場合は、MCP経由で公式ドキュメントを調査する。検索結果や記憶だけでAPIの仕様を推測して実装しない。

## 実装前に確認する事項

- 関数、インターフェース、構造体、列挙値の正式なシグネチャ
- 呼び出し順序と前提条件
- HRESULT、戻り値、失敗時の扱い
- COMオブジェクト、リソース、コールバックの有効期間
- スレッドセーフティ、同期、GPU完了条件
- リソースステート、アラインメント、サイズ、フォーマットの制約
- OS、SDK、Feature Level、Debug/Releaseによる利用条件

## 調査結果の扱い

調査結果が実装判断に影響する場合は、対象機能の設計文書または `docs/api-research.md` に次の内容を記録する。

- API名
- Microsoft LearnのページタイトルとURL
- 実装に関係する仕様
- 本プロジェクトで採用する呼び出し方
- 未解決の制約や確認事項

Microsoft Learnで仕様が確認できない場合は、その事実を記録し、別資料の内容を公式仕様として扱わない。APIの動作が実装の安全性や同期に関わる場合は、推測で進めず調査を継続する。
